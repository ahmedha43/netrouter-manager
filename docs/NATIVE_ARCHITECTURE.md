# NetRouter OS 0.1 — المعمارية الأصلية

## حد المنتج

NetRouter OS هو **نظام راوتر x86_64 قابل للإقلاع**، وNetRouter Manager هو **برنامج Windows x86_64 مستقل**. لا تعرض صورة النظام لوحة ويب افتراضياً. برنامج سطح المكتب هو سطح الإدارة الهندسي؛ يستلهم كثافة أدوات الإدارة التقنية من دون نسخ تخطيط أو شعار أو أيقونات أو بروتوكول أو أصول خاصة بطرف ثالث.

## طبقات التشغيل

| الطبقة | العملية أو الأثر | المسؤولية |
| --- | --- | --- |
| منصة الإقلاع | Buildroot وLinux وBusyBox وISO hybrid | يبني `bzImage` وrootfs ووسيط ISO قابل للإقلاع. |
| حد الامتياز | `netrouterd` | يقرأ حالة الراوتر ويطبق عمليات الشبكة المتحققة بصلاحية root. |
| النقل المحلي | Unix socket `/run/netrouterd.sock` | قناة إدارة داخل الجهاز، بصلاحيات ملف مقيدة. |
| النقل البعيد | TCP اختياري مع TLS 1.3 وmTLS | لا يعمل إلا بعد provision صريح لجميع الشهادات المطلوبة. |
| عميل الإدارة | `NetRouterManager.exe` | عميل Windows مستقل يستدعي البروتوكول ذي الإصدار ويعرض الحالة والواجهات. |

## عقد الوظائف في 0.1

الخدمة تقرأ حالة النظام والواجهات الحقيقية، وتنفذ مسارات مقيدة لتغيير حالة الرابط وتعيين عنوان CIDR واستبدال المسار الافتراضي. توجد قوالب DHCP/DNS وnftables firewall/NAT متحققة؛ التطبيق يتبع مسار **stage → validate → commit** لكي لا يُستبدل ملف الإعداد النشط عندما يرفض `dnsmasq --test` أو `nft -c` المحتوى الجديد.

لا يعني وجود handlers أن DHCP أو NAT أو firewall أصبح مدعوماً للإنتاج. لا تزال معاملات إعدادات متعددة الخطوات وrollback واختبار namespace/VM المتكامل خارج النطاق المتحقق. كذلك تبقى telemetry streams والنسخ الاحتياطي والتحديث وPPPoE وVPN وبروتوكولات التوجيه ودعم المعماريات الأخرى عملاً لاحقاً.

## بروتوكول الإدارة

العقد المشترك JSON بإصدار صريح. Unix socket محدود الحجم، وتُنشأ صلاحياته `0660`. الإدارة عن بعد لا تكون ممكنة دون TLS 1.3 وشهادة خادم وشهادات عميل موثقة؛ ترفض الخدمة فتح TCP إذا غاب أي مدخل شهادة. لا تُرسل الأسرار ضمن نماذج الطلبات أو واجهات الحالة.

## تنظيم البناء والتحقق

يحفظ `br2-external` وصفات NetRouter و`defconfig` خارج شجرة Buildroot، كما توصي وثائق Buildroot لتخصيصات المشاريع. [1] صورة x86_64 الحالية تفعّل Unix-domain sockets وvirtio block/network وconsole `ttyS0` لتمكين اختبار QEMU، وتنتج `rootfs.iso9660` كوسيط ISO hybrid عبر Syslinux/Isolinux.

| المستوى | البيئة | النتيجة المتحققة أو المطلوبة |
| --- | --- | --- |
| Unit | مضيف Linux | اختبارات Go تتحقق من المدخلات، socket، mTLS، وقوالب/مرحلة إعدادات الشبكة. |
| تكامل محلي | Linux معزول | تم إثبات Unix socket وإجابة `netrouterctl status`. |
| إقلاع image | QEMU x86_64 | تم إثبات إقلاع rootfs واختبار socket؛ وISO وصل إلى `Starting netrouterd: OK`. |
| تكامل بعيد | شبكة خاصة ذات عقدتين | مطلوب: اتصال EXE براوتر اختباري عبر mTLS. |
| عتاد | mini-PC x86_64 | مطلوب: قبول التخزين وبطاقات Ethernet والتثبيت غير الإنتاجي. |
