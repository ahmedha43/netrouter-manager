# مكوّنات NetRouter الأصلية

| المكوّن | الهدف | المسؤولية |
| --- | --- | --- |
| `cmd/netrouterd` | NetRouter OS x86_64 | خدمة مميزة تقرأ حالة النظام الحقيقية وتنفذ عمليات شبكة مقيدة بعد التحقق. |
| `cmd/netrouterctl` | NetRouter OS x86_64 | أداة تشخيص محلية على Unix socket. |
| `cmd/netrouter-manager` | Windows x86_64 EXE | عميل سطح مكتب Go/Fyne مستقل للاتصال المؤمّن وعرض الحالة والواجهات. |

## حدود النقل والأمان

تستمع الخدمة محلياً على `/run/netrouterd.sock` بصلاحيات `0660`. لا تبدأ مستمع TCP إلا عندما تُعطى القيم `--listen` و`--tls-cert` و`--tls-key` و`--tls-client-ca` معاً؛ عندها تستخدم TLS 1.3 وتفرض شهادة عميل موثقة. لا تختبر طلبات التعديل على محطة عمل أو شبكة إنتاجية.

تغطي الخدمة قراءة حالة النظام والواجهات، وتعديل حالة الرابط وتعيين CIDR واستبدال المسار الافتراضي ضمن حدود أوامر `ip` الضيقة. وتوجد الآن handlers لتوليد وتطبيق DHCP/DNS والجدار الناري/NAT. هذه handlers تكتب الإعداد في ملف مرحلي، وتتحقق منه عبر `dnsmasq --test` أو `nft -c`، ثم تستبدل الملف الدائم ذرياً؛ إذا فشل التحقق لا يتغير الملف النشط. لا توجد بعد طبقة معاملات إعدادات كاملة مع rollback لتغييرات وقت التشغيل أو اختبار تكاملي لخدمات الشبكة داخل namespace/VM.

## أوامر التحقق والبناء

```bash
cd native
go test ./...

cd ..
./scripts/build-native.sh
file artifacts/windows/NetRouterManager.exe
```

يبني السكربت Linux binaries في `artifacts/linux/` وعميل Windows في `artifacts/windows/NetRouterManager.exe`. EXE قابل للتجميع والتحقق من نوع الملف ضمن CI، لكن تشغيله على Windows حقيقي والاتصال براوتر اختباري لا يزالان خطوة قبول منفصلة.
